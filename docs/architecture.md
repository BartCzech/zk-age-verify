# Architecture

## Overview

Three independent components communicate through serialized data (base64 JSON and on-chain KV store). The private input (birth date) never leaves the prover's machine.

```
┌─────────────────────────────────────────────────────┐
│                  Prover's machine                    │
│                                                      │
│  Birth date ──► gnark circuit ──► ZK proof (base64) │
│  (secret)        (age_circuit.go)    + public witness│
└──────────────────────────┬──────────────────────────┘
                           │  JSON over CLI / tx
                           ▼
┌─────────────────────────────────────────────────────┐
│                  Cosmos SDK Chain                    │
│                                                      │
│  MsgSubmitAgeProof                                   │
│       │                                              │
│       ▼                                              │
│  keeper.SubmitAgeProof                               │
│    1. base64-decode proof + witness                  │
│    2. validate date vs block time (±24h)             │
│    3. groth16.Verify(proof, VK, witness)             │
│    4. SetVerified(address, timestamp) in KV store    │
│    5. emit age_verified event                        │
│       │                                              │
│       ▼                                              │
│  KV store: "verified/<address>" → RFC3339 timestamp  │
│                                                      │
│  QueryVerificationStatus → verified: true/false      │
└─────────────────────────────────────────────────────┘
```

## Data Flow

### Proof Generation (local, offline)

1. User invokes `go run zk/prover/main.go --year YYYY --month MM --day DD`
2. Prover compiles the circuit (registers solver hints for `std/math/cmp`)
3. Prover constructs a witness: private inputs (birth date) + public inputs (current date, minAge=18)
4. `groth16.Prove(ccs, pk, fullWitness)` — fails immediately if age < 18 (constraints unsatisfiable)
5. Public witness (current date, minAge) is extracted and serialized separately
6. Output: JSON with `proof` and `public_witness` as base64 strings

### On-chain Verification

1. User submits `MsgSubmitAgeProof{proof, public_witness, current_date, creator}`
2. Chain handler decodes base64 → raw bytes
3. Validates `current_date` is within 24h of block time (prevents using a future date)
4. Deserializes proof and public witness using gnark's native format
5. `groth16.Verify(proof, embeddedVK, publicWitness)` — cryptographically checks the proof
6. On success: stores `verified/<address>` → timestamp in KV store

### Verification Key Embedding

The VK is embedded as a `[]byte` literal in `chain/x/ageverify/keeper/vk_embedded.go`. This means:
- No file I/O at runtime
- VK is part of the binary — if the circuit changes, the binary must be rebuilt
- Generated once by `go run zk/setup/main.go`, copied manually into the chain module

## Component Details

### gnark Circuit (`zk/circuit/age_circuit.go`)

Implements `frontend.Circuit` interface. `Define(api)` builds a constraint system (R1CS) — it does not execute computation, it declares equations.

Key design choices:
- **MMDD encoding**: month and day collapsed into a single integer (month×100+day) for comparison. Avoids two separate comparisons.
- **BoundedComparator**: more efficient than unbounded `cmp.IsLess` because the max possible difference (1130) is known.
- **Arithmetic branching**: no if/else in circuits. `adjustedAge = baseAge - birthdayNotPassed` achieves the same result branch-free.
- **8-bit range check for age diff**: constrains `adjustedAge - minAge` to [0, 255], which proves non-negativity without a separate sign check.

### Keeper (`chain/x/ageverify/keeper/`)

| File | Role |
|------|------|
| `keeper.go` | Keeper struct: `cdc`, `storeService`, `logger` |
| `verifier.go` | `LoadVerificationKey()` + `VerifyAgeProof()` |
| `verification_store.go` | `SetVerified()` / `GetVerified()` via KV prefix store |
| `msg_server_submit_age_proof.go` | Main tx handler |
| `query_verification_status.go` | Query handler |
| `vk_embedded.go` | `var VKBytes = []byte{...}` — generated by Z2 |

KV store pattern (Cosmos SDK v0.50):
```go
storeAdapter := runtime.KVStoreAdapter(k.storeService.OpenKVStore(ctx))
store := prefix.NewStore(storeAdapter, []byte("verified/"))
store.Set([]byte(address), []byte(timestamp))
```

### Module Registration (`chain/x/ageverify/module/module.go`)

Implements `module.AppModule` and `module.AppModuleBasic`. Registers gRPC services via `RegisterServices(cfg module.Configurator)` — this wires `MsgServer` and `QueryServer` into the chain's gRPC router without protobuf codegen.

## Tech Choices

| Choice | Reason |
|--------|--------|
| Groth16 over PLONK | Smaller proof size, faster verification — matters for on-chain gas |
| BN254 curve | Ethereum-compatible, well-audited, gnark's primary target |
| Embedded VK | Simplest deployment — no file system dependency at runtime |
| `context.Context` in keeper | Cosmos SDK v0.50 standard — compatible with `storeService.OpenKVStore` |
| Manual types (no protoc) | Avoids protobuf toolchain dependency; viable because the message format is simple |
| 24h date tolerance | Proof generation and tx submission rarely span more than minutes; 24h is generous but safe |
